# 剧情漏洞审计（2026-10-23）

## 方法
三路证据，互不依赖：
- **A：无模型模拟器**。直接调用引擎纯函数（freshStory / sceneContext / pickCraft / applyScene / applyChoice / advanceTime / pickEnding），由桩代替 AI 写的幕。
  - 7 个包 × 每包 30–40 种策略 × 2 周目 × 10 个种子，共 4100 局。
  - 每个没走到的结局再用束搜索确认（束宽 3000）。
  - 脚本不在仓库里，在会话 scratchpad 的 `sim/`。
- **B：auditor 子 agent 只读通读** pack.ts / craft.ts，对照引擎代码。
- **C：真模型自动游玩**。走 `claude -p`，用自动游玩的 focus 策略。radio 跑完整局，其余包各跑前 12 幕。结果见文末，待补。

严重度：**高**＝玩家必然或很可能撞到；**中**＝特定路线会撞到；**低**＝细节不一致。

## 四、修复顺序（建议）
1. **引擎 E1–E7**，一次修好，所有包受益：
   - BeatDef / SetPieceDef 加 slots/places 约束，并让日程把到期的关键事件指向正确的地点。
   - 同一幕可以并入过期的关键事件。
   - 约定兑现改为「她在场，且这一幕给了兑现的选项」，或至少不让固定事件自动兑现。
   - 最后一天的约定也要结算。
   - 关键约定记在 beat.who 里好感最高、且在场的人名下。
   - 不绑角色的结局支持约定条件，并改掉平局规则。
   - 每改一处，都先在测试和模拟器里复现，再改。
2. **各包「高」级**文本修正。
3. **「中」「低」级**。第 2、3 步涉及剧情取舍的（例如 cicada 表决的时序），先列出备选写法，再请用户拍板。
