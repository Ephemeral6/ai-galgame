# 视觉改版方案：「夜场像素小剧场」

> 状态：实施中，进度见 §8。下文 §0–§7 是方案原稿。
> 日期：2026-10-23。依据：读 `hooks/register.tsx`、`hooks/fx.ts`、`hooks/art.ts`、`types/index.d.ts`、`tests/*.test.ts(x)`，以及 Claude Code 插件类型声明 `claude-code.d.ts`（随 plugin-authoring skill 分发，2.1.306）。

## 0. 先懂再画

**谁在用。** Claude Code 用户，以开发者为主，成年人。他们在 Claude 干活的间隙玩，一次玩一两幕，随时会被「Claude 干完了 / 等你批准」打断。情绪是放松的、有好奇心，但注意力是碎的：扫一眼就要知道「现在轮到我做什么」。只用键盘（数字键、字母键）。

**在什么设备上。** 终端里的侧边面板（Pane）。宽度不固定：测试用 100 列和 70 列；少于 80 列走 compact。终端背景可能深也可能浅，插件拿不到背景色（见 §5）。桌面 app 和 VS Code 没有 `Raster`，只有文字层（`claude-code.d.ts` 的 `Elements.terminal` 是唯一带 `Raster` / `Image` 的表面）。

**每一屏要让他完成的那一件事：**

| 画面 | 那一件事 |
| --- | --- |
| 标题 | 按 1 继续（或开新局） |
| 日程 / 地图 | 选一个地方去 |
| 场景对话 | 读完这一句，按 J；读完全部后进入选项 |
| 选项 | 选 1–N 中的一个 |
| 余波 | 读她的反应，按 J 继续 |
| 结局 | 品一下结局，决定二周目或看相册 |
| 相册 | 翻看回忆、信物、结局收集 |

## 1. 实测怎么做的，覆盖了什么

- **像素层**：写了一个草稿脚本，直接调用项目里的纯函数（`cardFrame`、`townMap`、`atmoBand`、`stageFrame`、`portraitFrame`、`relationGraph`），用 cicada 包的真实数据把 `Px[][]` 按「两行像素一格」画成 PNG，背景放深（#1e1e1e）、浅（#fafafa）两种各画一张。截图在 `docs/visual-redesign/`。
- **文字层**：在项目的草稿副本里加了一个只打印渲染树的测试（`claude plugin test`），拿到 100 列与 70 列下标题、日程、场景、选项、余波、相册六个状态的真实元素树（颜色、边框、按钮、Raster 尺寸）。项目本身没加任何文件，除了本文与 `docs/visual-redesign/` 下的 6 张参考图。
- **基线**：在原项目上跑 `claude plugin test`：**148 pass，0 fail**。
- **对比度**：按 WCAG 公式逐色算出，数值见 §2。
- **没覆盖**：没拿到真实终端的截图。插件 UI 不是网页，`ui_audit.mjs` 用不上；测试套件只测元素树，不画终端（参考文档原话：「The kit exercises the plugin's hooks ... not any surface's paint」）。所以边框字形、`plain` 按钮的热键前缀、主题的 dim 色这些终端实际绘制效果都标为「待实机确认」。设置、帮助、存档、剧本选择、成就这几屏只读了代码，没有出 mockup，只给规则（§4 第 13 条）。

## 2. 现状诊断

### 2.1 最朴素的几屏和具体原因

**(1) 场景屏：有立绘，没有「场景」。** 这是最大的一条。
- 舞台是 76×30 像素的透明画布，只放一到两只小动物，没有背景、没有地面、没有地点（`hooks/art.ts:120-145` `stageFrame`；`blank()` 全 null，`cells()` 把 null 编成终端默认色，`art.ts:183`）。截图 `now-scene-dark.png`：两只小动物浮在一片空白里，76 列中约 2/3 是空的。
- 视觉小说的基本语法是「背景 + 立绘 + 文本框」，现在缺了背景这一层，所以读起来像角色贴图，不像一幕戏。
- 氛围带是一条单独的 3 行粒子带，和舞台分开画（`register.tsx:1841`，`fx.ts:136-183`），只是几条虚线。蝉鸣（cicadas）的效果就是一串棕色短划。

**(2) 每屏都是一摞圆角框，没有主次。**
- 渲染树实测（100 列，选项状态）：顶栏圆角框 → 场景标题 → 氛围带 → 舞台 → 对话圆角框 → **每个选项各一个圆角框**（3 个）→ 键位栏。一屏 5 个 `round` 边框（`register.tsx:1250`、`1855`、`1889`）。
- 顶栏 5 行，每屏都有，而且 5 个角色的心形条全部列出（`register.tsx:1249-1281`）。场景里只有 1 人在场时，另外 4 行信息在和台词抢眼。
- 同一级的粗体主题色标题出现两次：顶栏的剧本名（`register.tsx:1252`）和场景名（`1850`）都是 `bold color={theme}`。
- 文字样式实测有 9 种以上：主题色粗体、默认粗体、DIM 灰、DIM 灰斜体、角色色粗体、角色色、名牌（色底黑字）、主题色「◈」、选项类型色等。终端只有一个字号，主次只能靠粗细、颜色、留白区分，样式一多就全部变平。

**(3) 标题页：标题出现两次，角色只是贴在一排。**
- 像素卡里是英文标题，紧接着是一个双线框里的中文标题（`register.tsx:1683-1691`），同一件事说了两遍，还用了两种边框（像素细框 + `double`）。
- 5 个头像是 5 个独立的 14 列 Raster，下面一行名字，没有地面、没有天空（`register.tsx:1692-1701`），截图 `now-title-light.png`。

**(4) 日程屏：地图前面先压了 24 行像素。**
- 每天第一个时段先出 12 行的「DAY n」卡，再出 12 行的地图（实测：两个 76×12 的 Raster），然后才是「午休，去哪里？」（`register.tsx:1746`、`1768-1770`）。在 40 行左右的面板里，问题会被挤到首屏以下。
- 地图上 10 个地点全是同一种房子，只换屋顶颜色；关着的是灰块（`fx.ts:234-256`，截图 `now-plan-light.png`）。

**(5) 浅色终端上整块不可见。** 这条是硬伤，不只是「朴素」。
- 「DAY 1」的字色 `#f4f4f4`（`register.tsx:1746`）在浅底上对比度 **1.05:1**，截图 `now-plan-light.png` 里几乎看不见。
- 白色的鹅（温璃）立绘在浅底上轮廓消失（截图 `now-title-light.png` 最右）。
- 文字层的强调色、主题色全部是为深底挑的（实测，背景 #ffffff）：

| 颜色 | 用途 | 深底 #1e1e1e | 浅底 #ffffff |
| --- | --- | --- | --- |
| `#f2c14e` ACCENT | 标题、设置值、约定色、默认主题 | 9.93 | **1.68** |
| `#8a8f98` DIM | 所有次要文字、旁白 | 5.13 | **3.25** |
| `#7fd1c7` reply / 「我」 | 选项、名字 | 9.41 | **1.77** |
| `#ffd54f` 白天主题 | 顶栏边框、场景标题 | 11.81 | **1.41** |
| `#f0e442` 色盲 promise | 选项 | 12.61 | **1.27** |

- 名牌把黑字 `#1e1a1a` 固定压在角色色上（`register.tsx:1863`）。深色角色读不清：警官 `#2d4b8e`（mauve 包）**2.06:1**，运动服 `#5e5e5e`（equalia 包）**2.66:1**。

**(6) 颜色没有唯一角色。** `#f2c14e` 同时是 ACCENT、默认主题色（`fx.ts:32`）、「约定」选项色（`register.tsx:1011`）。`#7fd1c7` 同时是「回话」选项色和「我」的名字色，还作为裸十六进制写在 `register.tsx:1176`、`1399` 两处。

### 2.2 八项诊断（按终端改写后的判据）

终端没有像素间距和字号，所以把判据改写成：间距以「格 / 行」为单位，刻度取 0·1·2·4；「字号级数」换成「文字样式级数」（粗细 × 颜色 × 暗淡的组合）。

| # | 项 | 结果 | 依据 |
| --- | --- | --- | --- |
| 1 | 主次 | 不通过 | 场景屏顶栏剧本名与场景名同为主题色粗体（`register.tsx:1252` / `1850`）；标题页标题出现两次 |
| 2 | 主动作 | 通过 | 标题页只有一个 `variant="primary"`；场景的选项是同一组动作 |
| 3 | 间距 | 不通过 | 标题框 `paddingX={3}`（`1688`），不在 0·1·2·4 里；边框 2 种（round、double），这一条本身合规 |
| 4 | 字体 | 不通过 | 场景屏文字样式 ≥ 9 种（见 2.1(2)），上限 4 |
| 5 | 颜色 | 不通过 | 裸十六进制散在 `register.tsx:1176`、`1399`、`1746`、`fx.ts`、`art.ts`；ACCENT 与 promise、默认主题色共用 |
| 6 | 可访问性 | 不通过 | 浅底：ACCENT 1.68、DIM 3.25、DAY 卡 1.05；名牌 2.06（`#2d4b8e`） |
| 7 | 默认审美 | 不通过 | 「到处圆角卡片」：一屏 5 个 round 框，每个选项各套一个 |
| 8 | 窄屏 | 通过 | 70 列测试通过（不画地图、选项不加框）；没有横向溢出的证据，但也没有实机截图 |

**通过 2 / 8，得分 3 / 10。**

## 3. 设计方向

### 3.1 一句话定调

**「夜场像素小剧场」：像素层是一块自带深色幕布的小银幕，文字层是印在终端纸面上的节目单。**

理由：
1. 终端背景色插件拿不到。与其让像素去适应深浅两种底，不如让每块像素画**自己带底**（深墨色幕布），深底、浅底终端上都是同一幅画。这顺带解决了 2.1(5) 里像素层的全部可见性问题。
2. 视觉小说要的「场景感」来自背景板。给舞台加上按地点和时段生成的背景与地面，一次补齐最缺的那一层。
3. 文字层退回终端的默认前景色和主题的 dim 色，强调色只留少数几处，并且由「芯片」（自带背景色的短标签）承载，颜色就不再依赖终端背景。
4. 深色、有质感、克制的配色，配上一个锋利的灯笼琥珀色作为唯一强调色。小动物和天色负责「可爱」，界面本身不抢戏。

### 3.2 设计令牌

终端里没有 CSS 变量。这里的「令牌」落成 TS 常量，集中放在一个新文件 `hooks/theme.ts` 里（纯数据和纯函数），组件只引用令牌名，不再写裸十六进制。

#### A. 像素层（固定，不随终端背景变）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `PX.screen` | `#17151f` | 幕布底：标题卡、DAY 卡、结局卡、地图、关系网、信物框的底 |
| `PX.frame` | `#3a3548` | 幕框暗边（与 screen 1.53:1，故意弱） |
| `PX.frameLit` | `#f2c14e` | 幕框四角的灯（闪烁）、选中 |
| `PX.title` | `#f4f1e8` | 像素大字（在 screen 上 16.4:1） |
| `PX.accent` | `#f2c14e` | 像素小字、门牌数字底（在 screen 上 10.8:1） |
| `PX.accent2` | `#f8bbd0` | 副标题（在 screen 上 11.2:1） |
| `PX.sky.<time>` | dawn `#3b2e5a→#f2a7a0`；day `#5aa7e0→#bfe3f2`；dusk `#2a2350→#f2a65a`；night `#0e1030→#2a2f5a` | 天空上下两色，中间量化成 4 档（控制色对数） |
| `PX.ground.<kind>` | room `#8a5d3e / #6e4a32`；street `#44464f / #6b6f7a`；field `#4f7a3a / #3f6a2e`；water `#2b4f7a / #3d6a9a`；roof `#5a5a66 / #3a3a46` | 地面主色 / 纹理色 |
| `PX.lamp` | `#ffd27a` | 窗灯、路灯 |

天气继续由 `themeOf()` 决定**主题色**，但主题色只用于像素层（粒子、天色偏移）和一根分隔线，不再给文字上色。

#### B. 文字层（随终端背景切换；`bg` 取值见 §5 第 2 条）

| 令牌 | 深底 `dark` | 浅底 `light` | 用途 |
| --- | --- | --- | --- |
| `T.text` | 不设颜色（终端默认前景） | 同左 | 正文、台词 |
| `T.subtle` | `dimColor`（主题的 dim 色） | 同左 | 元信息、旧台词、提示 |
| `T.accent` | `#f2c14e`（9.93） | `#8a5a00`（5.93） | 每屏唯一的屏标题、设置的当前值 |
| `T.kept` | `#81c784`（8.28） | `#2e7d32`（5.13） | 约定兑现、好感 +n |
| `T.broken` | `#ef8a8a`（6.88） | `#c62828`（5.62） | 约定违背、好感 −n、错误 |
| `T.event` | `#f0a070`（7.91） | `#b23c17`（5.91） | 今日事件「◆」 |
| `T.info` | `#9fc5e8`（9.23） | `#2f6db5`（5.28） | 生成中、八卦 |

括号里是对比度：深底列对 #1e1e1e，浅底列对 #ffffff，全部 ≥ 4.5。

**选项类型色走芯片**：`reply` / `observe` / `promise` 的颜色只做芯片**背景**，字色由 `inkOn(bg)` 在纯黑、纯白里挑对比更高的那个。数学上对任何背景色，两者中较高的一个都 ≥ 4.58:1，所以芯片不受终端深浅影响。

| 类型 | 图标 | default 芯片底 | cb（Okabe–Ito）芯片底 |
| --- | --- | --- | --- |
| reply 回话 | `❝` | `#7fd1c7` | `#56b4e9` |
| observe 观察 | `◎` | `#b0b6bd` | `#cc79a7` |
| promise 许诺 | `✦` | `#f2c14e` | `#f0e442` |

色盲配色保留，而且图标照旧不同，所以信息不只靠颜色区分。

**角色色**：
- 名牌：底 = 角色色，字 = `inkOn(角色色)`。实测：`#2d4b8e` 2.06 → 8.37；`#5e5e5e` 2.66 → 6.48；`#4f7a52` 3.48 → 4.96；`#8e6bb0` 4.01 → 4.88。
- 前景用的角色名和心形：`readable(c, bg)` 把角色色往白（深底）或往黑（浅底）按 5% 步长混，直到对比 ≥ 4.5。这是纯函数，放进 `theme.ts`。

#### C. 字符集

| 用途 | 字符 |
| --- | --- |
| 边框 | 只用 `round`，每屏最多 **1 个**（场景文本框 / 信件 / 结局正文） |
| 分隔线 | `─`（主题色或 dim），宽度 = 内容宽 |
| 时间线竖线 | `│` |
| 日历 | 已过 `▪`、今天 `◉`、事件 `◆`、普通 `·`（保持不变） |
| 进度 / 翻页提示 | `▼`（下一句）、`▶`（当前标签） |
| 状态 | `✓` 兑现、`✗` 违背、`○` 进行中、`★` 关键（保持不变） |
| 芯片 | 空格包裹：` 1 `、` 林小满 `，靠 `backgroundColor` 成块 |

不用 `double` / `bold` / `dashed` 边框（`dashed` 的实际字形没核实，见 §5）。

#### D. 间距（单位：横向格、纵向行）

- 横向刻度：**0 · 1 · 2 · 4**。文本框 `paddingX=1`；芯片与文字之间 1 格；同一行并列的组之间 2 格；缩进 2 格。
- 纵向刻度：**0 · 1**。区块之间空 1 行（`marginTop=1`），区块内部 0 行。像素「银幕」各层（天空带、舞台）之间 0 行，拼成一整幅。
- 去掉 `paddingX={3}`（`register.tsx:1688`）和 `paddingX={2}`（`1727`、`1802`）。

#### E. 文字层级（每屏 ≤ 4 级）

| 级 | 样式 | 用在 |
| --- | --- | --- |
| L1 | 像素字体（3×5，只有拉丁字母和数字） | 标题卡、DAY 卡、结局卡；只在像素层 |
| L2 | 粗体 + `T.accent`，或粗体 + 芯片 | 每屏一个屏标题；最新一句的名牌 |
| L3 | 默认前景（可粗体） | 正文、台词、选项文字 |
| L4 | `dimColor` | 元信息、旧台词、热键提示、花费 |

#### F. 强调规则

1. 每屏只有一个 L2 文字标题。场景屏的 L2 给场景名；剧本名降到 L4。
2. 强调色 `T.accent` 每屏最多出现在 2 处（屏标题 + 一个当前值）。
3. 颜色承载的信息必须同时有字形承载（图标、`+/-`、`✓✗`）。
4. 动效只在像素层，≤ 4 fps；进场是 6 帧过渡，之后只剩环境微动（眨眼、粒子、窗灯），设置里「动画：关」时全部静止。

## 5. API 没核实、需要实机确认的地方

| # | 内容 | 现在知道什么 | 怎么确认 |
| --- | --- | --- | --- |
| 1 | `plain` 按钮会不会自动画热键前缀 | 类型文档写着：plain 时画成「热键（accent 色）+ 冒号 + 标签」，如 `1: Yes`。如果属实，现在的 `1 教室`、`S 存档`、`▌❝ 1 回话` 实际显示为 `1: 1 教室`、`s: S 存档`，数字重复了一遍 | 在真实终端截一张日程屏。属实就去掉手写的 `1 ` / `S ` 前缀（§6 第 0 条） |
| 2 | 终端深浅怎么知道 | 插件拿不到终端背景色。`$.config.list()` 能读到 `/config` 菜单的行，文档示例就是找 `key === "theme"` 的行，但**取值集合没有类型**（推测有 dark / light / *-daltonized / *-ansi，未核实），而且主题是用户选的，不一定等于终端实际底色 | 在 `session.start` / `command.run` 里读一次（这两处可以写状态），打日志看取值；同时在设置里加手动项「背景：自动 / 深 / 浅」兜底 |
| 3 | 主题的 `dimColor` 实际是什么色 | 文档：「drawn in the theme's dim color」，具体值随主题。对比度**待测** | 深浅两种主题各截一张，像素取样后算 |
| 4 | Raster 的 1024 色对上限是每块还是整屏 | 文档：「its palette paints 1024 distinct color pairs at once and the rest as their nearest」，没说范围 | 原型实测单块 ≤ 62 对；整屏（标题 + 地图 + 舞台）合计也在 200 对以内，即使按整屏算也有余量 |
| 5 | `dashed` / `quote` / `arrow` 边框长什么样 | 只知道是合法的 borderStyle 名（文档列出 `single, double, round, bold, singleDouble, doubleSingle, classic, arrow, dashed, quote`），字形没见过 | 本方案只用 `round`，所以不依赖它们 |

| 8 | 16 色 / ANSI 主题的终端 | 十六进制颜色会被映射到最近的颜色，渐变天空可能出现色带 | 用 `dark-ansi` 主题截一张；必要时在 ANSI 主题下把天空换成纯色 |

## 7. 假设

- 大多数用户用深色主题。侦测失败时按 `dark`，因为 Claude Code 默认主题是深色（未核实，见 §5-2）。
- 面板高度按 40–60 行估算（测试里是 60）。「省 N 行」都按这个算。
- 地点种类的关键词推断只覆盖内置包。社区包没写 `backdrop` 时，回落到 `street`（室外）或 `room`（室内），由一个很短的关键词表决定，缺了也不会报错。
- 原型图（`docs/visual-redesign/proto-*.png`）只用来证明「背景板 + 地面 + 实底卡」可行，不是最终美术：窗的位置会被立绘挡住，室内墙色偏闷，这些在第 3 条实施时再调。
- 年轻用户偏好的研究结论（克制、深色、有质感）来自心理健康类应用的工作坊，用在这里只是借鉴，要用玩家的反馈验证。
